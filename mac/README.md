# «Великий & Могучий» для macOS

Диктовка в строке меню: нажали клавишу, говорите, отпустили — распознанный (и, если хотите, исправленный LLM)
текст вставляется туда, где стоит курсор, в любом приложении.
Обзор всего проекта, конфиденциальность и лицензии — в [корневом README](../README.md).

## Установка готовой сборки

Нужен Mac на Apple Silicon с macOS 14 или новее.

1. Скачайте `VelikiyMoguchiy-macOS-arm64.zip` со страницы
   [Releases](https://github.com/zigansh1n/velikiy-moguchiy/releases), распакуйте и перенесите
   `VelikiyMoguchiy.app` в «Программы».
2. Сборка **не подписана сертификатом Apple** (только ad-hoc подпись), поэтому Gatekeeper при первом запуске
   её не откроет. Либо: «Системные настройки → Конфиденциальность и безопасность» → внизу «Всё равно открыть»;
   либо в Терминале снимите карантин:

   ```bash
   xattr -dr com.apple.quarantine /Applications/VelikiyMoguchiy.app
   ```

3. При первом запуске откроется окно «Начало работы» (потом — из меню значка): дайте доступ к **микрофону**,
   **универсальному доступу** и **мониторингу ввода** (таблица ниже), затем в настройках укажите ключ провайдера
   распознавания (для русского — DashScope, модели Qwen; как его получить — [`docs/DASHSCOPE-KEY.md`](../docs/DASHSCOPE-KEY.md))
   и нажмите «Проверить ключ».
   Нет ключа — приложение предложит распознавать речь прямо на Mac: русская модель Vosk (около 30 МБ, sherpa-onnx)
   скачается один раз с проверкой SHA-256, звук никуда не уходит. Ключ можно указать позже; приложение никогда не
   меняет выбранное распознавание само, если ключ задан. После «Не сейчас» предложение больше не появляется, а
   локальную модель можно выбрать в настройках распознавания.

У ad-hoc подписи нет постоянной «личности», поэтому после **каждого обновления** macOS может снова спросить
разрешения или молча считать их выданными старой версии: снимите и заново поставьте галочки в
«Конфиденциальность и безопасность». Автообновления нет, пока у проекта нет Developer ID: раз в день приложение
проверяет [Releases](https://github.com/zigansh1n/velikiy-moguchiy/releases) и, если вышла новая версия, показывает
в меню «Доступна новая версия …» со ссылкой. Скачивает и ставит её пользователь.

## Сборка из исходников

Нужны Xcode, Rust (`rustup`), `cmake` и [XcodeGen](https://github.com/yonaskolb/XcodeGen):
`brew install cmake xcodegen`.

```bash
git clone https://github.com/zigansh1n/velikiy-moguchiy.git
cd velikiy-moguchiy/mac
cp MacApp/Config/Secrets.xcconfig.example MacApp/Config/Secrets.xcconfig   # по желанию: свой bundle id для форка
bash scripts/setup-codesign-identity.sh   # по желанию, один раз: разрешения не слетают между сборками
make build          # XcodeGen + ядро на Rust + приложение + встроенный CLI
make install-app    # копирует VelikiyMoguchiy.app в /Applications
```

Только ядро и его тесты: `cargo test --workspace` в этой папке. CI собирает приложение так же
(`.github/workflows/build-apple.yml` в корне репозитория). Логика приложения (без интерфейса):
`xcodebuild test -project MacApp/VelikiyMoguchiy.xcodeproj -scheme VelikiyMoguchiyLogicTests`.

Bundle id сборок — `io.github.zigansh1n.velikiy-moguchiy` (`MacApp/Config/Base.xcconfig`); к нему macOS привязывает
разрешения и настройки. Форку лучше задать свой в `MacApp/Config/Secrets.xcconfig` (файл не попадает в git).

## Разрешения

| Разрешение | Зачем | Без него |
|---|---|---|
| Микрофон | запись речи | запись не начнётся |
| Универсальный доступ | вставка текста (имитация `Cmd+V`) | текст остаётся в буфере обмена, вставлять вручную |
| Мониторинг ввода | глобальная клавиша диктовки (по умолчанию **Fn**) | клавиша не срабатывает |
| Распознавание речи | только для провайдера Apple Speech (macOS 26+) | остальные провайдеры работают |
| Камера | только «Данные для чтения по губам» и экспериментальный режим «губы»; оба по умолчанию выключены | ничего не меняется |

## Данные и настройки

Настройки, ключи, история, записи диктовок и модели лежат в `~/.velikiy-moguchiy/` (`config.yaml`, `dictionary.txt`,
`history.db`, `recordings/`, промпты; полный список ниже). Если остался только каталог `~/.koe/` от сборок до
переименования, приложение продолжает работать с ним. Файл `config.yaml` создаётся при первом запуске,
с комментариями к полям.

Что и куда отправляется, — в [PRIVACY.md](../PRIVACY.md). Сторонние лицензии — в [THIRD_PARTY.md](THIRD_PARTY.md)
и в окне «О программе → Лицензии».

## Как это работает

1. Нажмите клавишу диктовки (по умолчанию **Fn**). Режимы (`hotkey.trigger_mode`): `hold` — держите, пока
   говорите; `toggle` — нажали, чтобы начать, и ещё раз, чтобы закончить; `double_tap` — двойное нажатие
   начинает, одиночное заканчивает. Клавишу можно сменить на Option, Command, Control, код клавиши или сочетание.
2. Звук в реальном времени уходит провайдеру распознавания с вашим ключом (для русского — Qwen через DashScope)
   или остаётся на Mac с локальным провайдером.
3. Плашка на экране показывает промежуточный текст, пока вы говорите, и остаётся до конца исправления LLM.
4. Итоговый текст вставляется в активное поле ввода. Если включены шаблоны, цифрами `1–9` можно переписать
   результат по шаблону; такой вариант копируется в буфер обмена.

Провайдеры:

- **облачные:** Qwen (DashScope), Doubao и другие из `velikiy-moguchiy-asr/`;
- **локальные:** Apple Speech (macOS 26+, без ключа), MLX (модели Qwen3-ASR на Apple Silicon), sherpa-onnx (CPU);
- **LLM для исправления:** OpenAI Chat Completions и Responses, Anthropic Messages, совместимые шлюзы, локальные
  модели MLX.

## Файлы в `~/.velikiy-moguchiy/`

| Файл | Что в нём |
|---|---|
| `config.yaml` | основные настройки: распознавание, LLM, звуки, клавиша, словарь |
| `dictionary.txt` | словарь: по одному термину в строке, `#` — комментарий; идёт и в подсказки распознаванию, и в LLM |
| `system_prompt.txt` | правила исправления текста для LLM |
| `user_prompt.txt` | шаблон запроса к LLM; подстановки `{{asr_text}}`, `{{interim_history}}`, `{{dictionary_entries}}` |
| `dictionary-it-ru.txt` | стартовый словарь IT-терминов и брендов, копируется из приложения |
| `history.db` | история и статистика диктовок (SQLite) |
| `recordings/` | звук каждой диктовки (AAC, `.m4a`), включая отменённые и неудачные; по умолчанию включено (`history.save_recordings`), записи старше 30 дней удаляются (`history.recordings_retention_days`) |
| `lipdata/voiced/` | видео с камеры и распознанный текст диктовок, только если включено `lipdata.capture_video` (по умолчанию выключено) |
| `lips_training/` | состояние и результаты «Обучить на мне», если вы его запускали |
| `models/` | локальные модели; у каждой папки файл `.koe-manifest.json` со списком файлов и их sha256 |

Большую часть этого можно править в окне настроек (из меню в строке меню). Если файла промпта нет или он пустой,
используется встроенный текст из `velikiy-moguchiy-core`; существующий `user_prompt.txt` приложение не перезаписывает.

## Режим «губы» (эксперимент)

Включается в `config.yaml`: `experimental.lips: true` и клавиша `hotkey.lips_key`. При первом нажатии клавиши
приложение объясняет, что скачает, и после согласия ставит всё само, с прогрессом и кнопкой «Отменить» (загрузка
продолжается с того же места). После «Не сейчас» клавиша только напоминает, а установить можно в «Настройки →
Данные для чтения по губам → Режим «губы»». Что ставится:

- базовая модель MultiVSR у её авторов (Оксфорд, около 4,5 ГБ; её лицензия не указана, поэтому в проекте её нет);
- дообученная модель губ, самая новая из [Hugging Face](https://huggingface.co/z1gansh1n/velikiy-moguchiy-lips) и
  выпусков `lips-*` [velikiy-moguchiy-models](https://github.com/zigansh1n/velikiy-moguchiy-models/releases): сначала с
  Hugging Face, если он недоступен — с GitHub;
- [uv](https://github.com/astral-sh/uv), Python 3.13 и библиотеки из `lipread/uv.lock` (по хэшам из lock-файла,
  ffmpeg — пакет `imageio-ffmpeg`), код MultiVSR на закреплённом коммите.

Проверки: у моделей — SHA-256 из `SHA256SUMS.txt`, сверенные с хэшами Hugging Face и GitHub; выпуски новее
`lips-0.1` должны быть подписаны ключом проекта (`SHA256SUMS.txt.sig`, Ed25519, открытый ключ встроен в приложение;
подписать — `tools/models/sign_lips_release.py`); у базовой модели — закреплённый SHA-256; код MultiVSR сверяется
пофайлово с `lipread/multivsr_files.sha256`, потому что архивы GitHub не гарантируют одинаковых байтов. Свои
чекпойнты сервис загружает только как тензоры (`weights_only=True`).

Всё лежит в `~/.velikiy-moguchiy/`: модели — в `models/lips/`, окружение сервиса — в `lips/` (журнал установки —
`lips/setup.log`). Код сервиса берётся из самого приложения. Раз в день приложение проверяет, нет ли модели новее, и
предлагает обновить её из меню.

Разработчику загрузка не нужна: приложение, собранное из исходников (`make build`), запускает сервис из папки
`lipread/` этого же репозитория, если в ней есть `.venv` (`lipread/setup.sh`). Другую папку задаёт
`lips.service_dir`. Сборки из CI этого пути не знают.

## Сообщить о проблеме

Пункт меню «Сообщить о проблеме…» собирает версию приложения, версию macOS и последние строки лога этого запуска,
скрывает ключи, токены, почту, тексты диктовок и имя пользователя в путях и показывает всё это: текст можно
поправить. Ничего не отправляется само: «Открыть на GitHub» открывает в браузере заполненную форму
[«Сообщить о проблеме»](https://github.com/zigansh1n/velikiy-moguchiy/issues/new?template=problem.yml), её
отправляете вы.

## Командная строка и локальные модели

Внутри приложения лежит CLI `velikiy-moguchiy` (`Contents/MacOS/velikiy-moguchiy-cli`; `make build` ставит и его):

```bash
velikiy-moguchiy model list                              # какие модели есть и в каком они состоянии
velikiy-moguchiy model pull mlx/Qwen3-ASR-0.6B-4bit      # скачать (с проверкой sha256)
velikiy-moguchiy model status mlx/Qwen3-ASR-0.6B-4bit
velikiy-moguchiy model remove mlx/Qwen3-ASR-0.6B-4bit    # удалить файлы, манифест остаётся
```

Скачать модель можно и в настройках, на вкладке распознавания. Если и распознавание, и LLM локальные (MLX), приложение
работает совсем без сети.

## Устройство и функции сборки

- **Оболочка на Objective-C** (`MacApp/`): клавиша, запись звука, буфер обмена и вставка, строка меню, история.
- **Ядро на Rust** (`velikiy-moguchiy-core`, статическая библиотека `libvelikiy_moguchiy_core.a`, связь через C FFI):
  провайдеры распознавания (`velikiy-moguchiy-asr`), исправление LLM, настройки, модели, сборка итогового текста.
- **Swift-пакеты** `MLXBridge` и `AppleSpeechBridge`: мосты к MLX и к Apple SpeechAnalyzer через C FFI.

Локальные провайдеры включаются функциями Cargo в `velikiy-moguchiy-core/Cargo.toml`: `mlx`, `apple-speech`,
`sherpa-onnx` (по умолчанию все три). `make build` и релизная сборка собирают ядро с `--no-default-features --features
apple-speech,sherpa-onnx` (`Makefile`, `MacApp/project.yml`): облачные провайдеры, Apple Speech и sherpa-onnx (MLX
пока не собирается на Xcode 26.3). sherpa-onnx линкуется в варианте без синтеза речи (`scripts/sherpa-onnx-libs.sh`):
обычные библиотеки тянут в приложение espeak-ng под GPL-3.0. Функция `wetype-offline` никогда не входит ни в сборку
по умолчанию, ни в релиз.
