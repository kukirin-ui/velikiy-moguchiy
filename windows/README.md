# «Великий & Могучий» для Windows

Голосовой ввод для Windows 10 и 11: держите клавишу, говорите, отпустите — текст появится там, где мигает курсор, в
любой программе. Ранняя версия (этап 1): диктовка работает так же, как на Mac, чтение по губам — следующий этап
([LIPREAD.md](LIPREAD.md)).

## Как пользоваться

1. Распакуйте `VelikiyMoguchiy-Windows-x64.zip` из [релизов](https://github.com/zigansh1n/velikiy-moguchiy/releases)
   и запустите `VelikiyMoguchiy.exe`. Сборка не подписана: если SmartScreen предупредит, нажмите «Подробнее →
   Выполнить в любом случае».
2. В трее у часов появится значок, при первом запуске откроются настройки:
   - **Qwen в облаке** — вставьте свой ключ DashScope (Alibaba Cloud Model Studio → API Keys). Модель по умолчанию
     — Qwen Omni: понимает голосовые команды («новая строка», «отправь») и чистит речь; Qwen-ASR пишет дословно.
   - **Локально** — распознавание на процессоре без интернета (sherpa-onnx, многоязычная модель с русским). Нажмите
     «Скачать локальную модель», это около 340 МБ. Качество ниже, чем у Qwen.
3. Клавиша по умолчанию — **правый Ctrl**. Режимы:
   - «Удерживать, пока говорю» — запись идёт, пока клавиша нажата;
   - «Удерживать или коротко нажать» — удержание как выше, а короткое нажатие начинает запись без рук до следующего
     нажатия;
   - «Нажать — начать, нажать ещё раз — закончить» и «Двойное нажатие».

   **Esc** во время записи отменяет её. Сочетание с клавишей (например, правый Ctrl+C) запись тоже отменяет:
   программа понимает, что вы набираете сочетание, а не диктуете.
4. Внизу экрана появляется плашка: уровень звука, распознанный текст, ошибки. Она не забирает фокус и пропускает
   щелчки мыши.

Если пока вы говорили, активное окно сменилось, текст не вставляется, а остаётся в буфере обмена (Ctrl+V).

Настройки хранятся в `%USERPROFILE%\.velikiy-moguchiy\config.yaml` — тот же файл и формат, что на Mac: словарь,
сниппеты, LLM-коррекция, `paste.auto_return`, `recording.auto_stop_silence_s` и остальное работают так же.
Клавиша для Windows лежит в `windows.trigger_key` (`right_ctrl`, `right_alt`, `caps_lock`, `scroll_lock`, `pause`,
`insert`, `f1`…`f24`), режим — в общем `hotkey.trigger_mode`. Журнал: меню значка → «Открыть журнал».

### Ограничения этапа 1

- Текст вставляется через буфер обмена и Ctrl+V. В окна программ, запущенных от имени администратора, вставить
  нельзя: Windows не пускает туда ввод от обычных программ. Перехват клавиши в таких окнах тоже не работает.
- Нет печати по ходу речи (`experimental.live_insert`) и контекста поля для Qwen Omni (текст перед курсором):
  на Mac это сделано через Accessibility, для Windows нужна UI Automation.
- Нет перевода, вопросов к выделенному тексту, правки голосом, истории и записи диктовок — это отдельные окна
  Mac-приложения, их перенос — следующие шаги.
- Подписи нет; автообновления нет.

## Почему так устроено

Выбирали из трёх вариантов. Главные условия: переиспользовать как можно больше Rust-ядра из `mac/` и не отпугнуть
участников сообщества сложной сборкой.

| | Tauri | **Чистый Rust + windows-rs** | WinUI / C# поверх ядра |
|---|---|---|---|
| Ядро из `mac/` | напрямую, как Rust-крейт | **напрямую, как Rust-крейт** | через C ABI (cbindgen) и P/Invoke |
| Языки в проекте | Rust + HTML/JS (+ npm) | **только Rust** | Rust + C# + XAML |
| Сборка | Cargo + Node + WebView2 | **один `cargo build`** | Cargo + .NET SDK + Windows App SDK |
| Плашка без фокуса поверх окон | возможна, но через обходы WebView | **обычные флаги окна Win32** | возможна |
| Размер и зависимости | WebView2, сотни МБ памяти | **один exe** | рантайм .NET / Windows App SDK |
| Порог входа для новичка | низкий для веба | средний (Rust) | средний (C#), но два языка |

Выбран **чистый Rust**: ядро подключается как обычная зависимость и вызывается теми же функциями `sp_core_*`, что
и из Objective-C на Mac, без отдельного слоя привязок. Весь проект собирается одной командой, в нём один язык, а
системная часть Windows небольшая и изолирована в одном крейте. Интерфейса у программы немного (значок, плашка,
одно окно настроек), поэтому веб-движок Tauri был бы тяжелее, чем нужно, а C# добавил бы второй язык и вторую
систему сборки ради трёх окон.

### Что взято из Rust-ядра как есть

Из `mac/velikiy-moguchiy-core` и `mac/velikiy-moguchiy-asr` используется всё платформенно-независимое — почти всё
ядро:

- провайдеры распознавания: Qwen realtime через DashScope с ключом пользователя (несколько ключей с переключением),
  Doubao, GLM, MiMo, локальный sherpa-onnx; загрузка и проверка локальных моделей;
- сессия диктовки: буферизация звука, ожидание итогового текста, LLM-коррекция, словарь, сниппеты, голосовые
  команды («новая строка», «отправь»), режимы вывода по типу приложения, инструкции для Qwen Omni;
- `config.yaml` с миграциями, датчик тишины для автоостановки, индикатор уровня звука.

В ядре понадобилась одна правка: права доступа к файлам (`chmod 600` для `config.yaml`) обёрнуты в `cfg(unix)`, а
домашней папкой при отсутствии `HOME` считается `USERPROFILE`. Без этого ядро не собиралось под Windows.

Не переносится: печать в поле и чтение текста у курсора (`unicode_typing.rs`, `live_insert.rs`, `app_context.rs`)
сделаны на macOS Accessibility; вне macOS ядро само их отключает. Mac-модули MLX и Apple Speech под Windows не
собираются.

## Устройство

```
windows/
├── app/        крейт velikiy-moguchiy-windows, exe «VelikiyMoguchiy»
│   └── src/
│       ├── controller.rs   сессия глазами пользователя: жесты → ядро → плашка → вставка
│       ├── hotkey.rs       клавиша и режимы: удержание, короткое и двойное нажатие, Esc, сочетания
│       ├── core_bridge.rs  вызовы sp_core_* и колбэки ядра
│       ├── audio.rs        микрофон в любом формате → 16 кГц моно PCM16, кадры по 100 мс
│       ├── settings.rs     окно настроек ↔ config.yaml
│       ├── app_id.rs       Telegram.exe → org.telegram.desktop и т. п. для категорий приложений ядра
│       ├── logfile.rs      журнал в файл
│       └── win_app.rs      сборка всего вместе под Windows
│   build.rs + resources/   иконки (из иконки Mac-приложения), манифест, версия файла
├── win32/      крейт velikiy-moguchiy-win32: всё, что говорит с Win32
│   └── src/  hook.rs (клавиатура), input.rs (Ctrl+V), clipboard.rs, overlay.rs (плашка),
│             tray.rs, form.rs (окно настроек), mic.rs (cpal/WASAPI), shell.rs (цикл сообщений)
└── README.md, LIPREAD.md
```

Логика (`controller`, `hotkey`, `audio`, `settings`, `app_id`) не знает о Windows и тестируется на любой ОС:
системные вызовы в тестах заменены подставным `Host`. Всё, что приходит из хука клавиатуры, потоков ядра и
микрофона, складывается в очередь и обрабатывается в одном потоке интерфейса — так обработчики никогда не
вкладываются друг в друга. Хук клавиатуры работает в отдельном потоке, только решает, что за жест, и сразу
возвращает управление: Windows молча снимает хуки, которые медлят.

## Сборка

Нужны Rust (stable, MSVC) и Visual Studio Build Tools с компонентом C++ и CMake (для libopus):

```
cd windows
cargo build --release
cargo test
```

Готовый exe — `target\release\VelikiyMoguchiy.exe`. Функция `sherpa-onnx` (включена по умолчанию) при сборке скачивает
готовые библиотеки sherpa-onnx; без локального распознавания: `cargo build --release --no-default-features`.
В `.cargo/config.toml` включён статический CRT: библиотеки sherpa-onnx собраны с `/MT`.

Логику можно разрабатывать и на Mac или Linux: `cargo test -p velikiy-moguchiy-windows --no-default-features`
собирает и проверяет всё, кроме Win32-части.

CI: задание «Windows app» в `.github/workflows/tests.yml` собирает и тестирует на `windows-latest` при изменениях в
`windows/` или в ядре; `.github/workflows/build-windows.yml` делает `VelikiyMoguchiy-Windows-x64.zip`, а тег `v*`
добавляет его в черновик релиза.
