# newdata: сборщик НОВОГО русского talking-head видео (вне MultiVSR)

Цель: клипы лица для обучения чтению по губам из роликов, которых **нет** в `data/public_meta/ru.jsonl`
(MultiVSR-ru, 7682 ролика; дополнительно исключаются id из `ru_csv.jsonl` и `fetch/selection_ru.jsonl`).
Формат результата тот же, что в `data/public/`: `data/public_new/<id>.mp4` (кроп лица 224x224, 25 к/с, H.264, как делает
`preprocess.py` для MultiVSR), `<id>.txt` (метка), `<id>.json` (`video_id, start, end, source="newdata-ru", scores{...}`).
Имя клипа: `<video_id>__00000_<стартовый кадр на 25 к/с>`.

## Запуск

```bash
cd velikiy-moguchiy/lipread/newdata      # из корня клона репозитория
# тестовая партия: 50 роликов через все сита
python3 ../../tools/mem_guard.py -- .venv/bin/python collect.py run --limit-videos 50 --workers 4 --procs 2
# полный сбор в фоне, цель 100 часов, потолок диска 30 ГБ для data/public_new
nohup python3 ../../tools/mem_guard.py --reserve-gb 4 --min-free-pct 12 -- \
  caffeinate -i nice -n 5 .venv/bin/python collect.py run --target-hours 100 > work/full_run.log 2>&1 &
.venv/bin/python collect.py report          # проценты по ситам, причины отказов, часы, диск
touch STOP                                  # мягкая остановка (дорабатывает текущие ролики); или kill <PID>
tail -f progress.log
```

Окружение: `newdata/.venv` (Python 3.11: mediapipe 0.10.21, opencv, scipy, silero-vad/torch, soundfile). Распознавание речи:
GigaAM v3 RNNT (MLX, пакет `gigaam_mlx`) в отдельном окружении (путь к интерпретатору — `GIGAAM_PY` в `collect.py`,
по умолчанию `~/.venvs/gigaam`), `asr_worker.py` держит модель в памяти и отвечает построчно по stdin/stdout. Поиск ручных
субтитров: внешняя утилита `transcript find/get --manual-only` (путь задаётся переменной `YT_TRANSCRIPT_BIN`).
Возобновляемость: всё состояние в `state.db` (SQLite): видео, события сит, выполненные поисковые запросы; повторный
запуск продолжает с того места, клип считается готовым при наличии `<id>.json` (он пишется последним).

## Сита (в порядке применения; события каждого сита в таблице `events`, проценты: `collect.py report`)

| сито | что проверяется | отказ (reason) |
|---|---|---|
| s1_flat | метаданные поиска без загрузки: длительность 5-120 мин, не live, доля кириллицы в названии >= 0.4, ключевые слова: музыка/клипы, мультфильмы, игры, фильмы/сериалы/озвучка/дубляж/перевод, закадровые документалки, туториалы с экраном, реакции, нарезки | `duration, live, lang_title, kw_*` |
| s1b_thumb | 3 автокадра превью с i.ytimg.com (картинки, без API видео): лицо с рамкой >= 60 px (в кадре 480x360) в >= 2 из 3, одиночное, поворот носа <= 0.35 | `no_face_thumbs` |
| s2_meta | полные метаданные `yt-dlp -j`: категория (Music, Gaming, Film & Animation, Pets), поле языка, ключевые слова в описании, доля кириллицы, есть формат 240-360p, fps >= 24, <= 3 принятых ролика на канал (проб не больше 6) | `category_*, lang_field, kw_*, lang_text, no_360p, fps_meta, channel_cap` |
| s2b_story | раскадровка YouTube sb0 (6 листов, ~50 плиток по всему ролику, тоже картинки из info `yt-dlp -j`): лицо в >= 30% плиток, медианная высота (в пересчёте на 360p) >= 80, второе лицо крупнее 50% в <= 30%, поворот <= 0.35 в >= 30% | `story_face, story_small, story_multi, story_yaw` |
| s3_tech | проба 30 с из середины (360p, `-c copy` без перекодирования): fps >= 24, битрейт с поправкой на кодек (H.264 x1, VP9 x1.4, AV1 x1.9) >= 100 кбит/с, чёткость лица (дисперсия лапласиана 96x96) >= 25 | `fps, bitrate, blurry, short` |
| s4_face | MediaPipe FaceMesh: лицо в > 70% кадров, высота рамки в терминах S3FD >= 90 px (360p), второе лицо крупнее 50% в <= 20% кадров, анфас (поворот <= 0.15 в >= 70% кадров) | `face_frac, face_small, multi_face, not_frontal` |
| s5_speech | Silero VAD: речи >= 40% пробы; GigaAM: >= 1.2 слова/с в речевых кадрах | `no_speech, asr_sparse` |
| s6_sync | активный говорящий в пробе: корреляция сигнала рта (раскрытие/площадь/тёмность внутри губ) с речевой энергией 100-3500 Гц, максимум по сдвигу +-5 кадров >= `probe_sync_min` | `low_sync` |
| s7_video | после загрузки ролика: для всех сегментов с хорошим лицом считается корреляция губы/звук; нулевая модель - тот же сегмент с речевой энергией из другого места ролика (сдвиг >= 15 с), порог = 95-й процентиль нулевой модели (не ниже 0.12); ролик принимается, если доля сегментов выше порога >= 0.18 и средняя разность с нулевой моделью >= 0.04 | `few_face_segments, low_sync, no_segments` |
| s8_clips | сегменты 2-10 с: непрерывный трек лица (<= 3 подряд пропущенных кадра, нет скачков), лицо p10 >= 80 px, анфас p90 <= 0.18, второе лицо <= 10% кадров, чёткость, синхронность сегмента выше порога s7; метка GigaAM; если есть ручные субтитры - WER(субтитры, GigaAM) <= 15% (полуглобальное выравнивание, края не штрафуются), нет сегментов с `[музыка]`/аплодисментами; 0.8-5.5 слов/с, >= 3 слов | `asr_empty, wps, no_caption, noise_tag, wer` |

Сегментация: Silero VAD -> речевые интервалы -> склейка в сегменты 2-10 с с разрезом по самым длинным паузам; границы
реплик ручных субтитров (если есть) получают бонус при выборе точки разреза; к краям добавляется до 0.12 с тишины.
Метка клипа: GigaAM v3 по самому клипу, нормализация: нижний регистр, без знаков препинания и тегов.

## Кроп

`vision.py`: рамка лица по 468 точкам FaceMesh пересчитывается в рамку S3FD (калибровка `calib.json`: на 160 кадрах S3FD
дал высоту x1.12 и ширину x0.98 от рамки FaceMesh, центр выше на 0.05 высоты), затем как в `fetch/run.py`/
`multivsr/preprocess`: медиана 13 по центру и размеру, запас 0.4, серое поле 110, ресайз 224x224, libx264 crf 23.

## Сеть и ограничения

* yt-dlp идёт с куками пользователя (`../fetch/cookies.txt`, содержимое не копируется и не печатается), не более 2 одновременных
  обращений к YouTube, `--sleep-requests 1 --sleep-interval 2 --max-sleep-interval 6`.
* 3 подряд блокировки/бот-проверки: сбор останавливается, пишется `STOPPED_BOT`, уходит уведомление macOS (не чаще раза в 15 мин).
  После разбора удалите `STOPPED_BOT` и запустите снова.
* Сырые загрузки живут в `work/tmp/<id>/` и удаляются сразу после нарезки. Потолок: `data/public_new` <= 30 ГБ и >= 12 ГБ
  свободно на диске, иначе остановка. Тяжёлые задачи запускаются под `tools/mem_guard.py`; BLAS ограничен 1 потоком
  (иначе несколько процессов NumPy доводили load average до 700).

## Результаты тестовой партии (2026-10-13)

50 роликов дошли до сита s2 (из поисковых запросов, 203 кандидата на входе s1). Проценты прохождения («вошло» -> «прошло»):

| сито | вошло | прошло | % |
|---|---|---|---|
| s1_flat (метаданные поиска) | 203 | 113 | 55.7 |
| s1b_thumb (превью) | 99 | 50 | 50.5 |
| s2_meta (полные метаданные) | 50 | 28 | 56.0 |
| s2b_story (раскадровка) | 28 | 22 | 78.6 |
| s3_tech (fps, битрейт, чёткость) | 22 | 22 | 100 |
| s4_face (лицо в пробе) | 22 | 5 | 22.7 |
| s5_speech (речь, GigaAM) | 5 | 5 | 100 |
| s6_sync (проба) | 5 | 4 | 80.0 |
| s7_video (весь ролик) | 4 | 2 | 50.0 |
| s8_clips | 2 | 2 | 100 |

Итого из 50 роликов принято 2 (4%): 225 клипов, 0.37 часа (169 клипов 17.2 мин из 89-минутной лекции с ручными субтитрами,
56 клипов 5.1 мин из 41-минутного монолога без субтитров). Причины отказов: s1: не кириллица в названии (45), длительность (39),
музыка (3), озвучка/фильм (3); превью без лица (49); s2: live (9), поле языка не ru (9), музыка (2), нет 360p (1), озвучка (1);
раскадровка: yaw/мульти-лицо/мало лиц по 2; s4: мало кадров с лицом (7), не анфас (4), лицо мельче 90 px (4), второе лицо (2);
s6: low_sync (1); s7: low_sync (2). Среди сегментов принятого ролика с субтитрами s8 отбросил по WER > 15%: 36, по слову/с: 4, пустое ASR: 2.

Распределение синхронности (корреляция губы/звук, максимум по сдвигу +-5 кадров):

| выборка | n | p5 | p25 | медиана | p75 | p95 |
|---|---|---|---|---|---|---|
| сегменты с хорошим лицом, реальный звук | 1518 | -0.01 | 0.14 | 0.27 | 0.40 | 0.61 |
| те же сегменты, звук из другого места (нулевая модель) | 3036 | -0.07 | 0.06 | 0.16 | 0.26 | 0.43 |
| принятые клипы (выше порога ролика 0.41-0.42) | 225 | 0.43 | 0.47 | 0.53 | 0.61 | 0.73 |

Уровень ролика: принятые - доля сегментов выше порога 0.325 и 0.295, разность со средним нулевой модели 0.178 и 0.150;
отклонённые - 0.112/0.051, 0.063/0.010 (x3tGKcKmrnQ: разговор двоих с чередующимися планами; 1JI1I5d4cmc: солист-блогер,
по кадрам похож на нормального говорящего, то есть ложный отказ). WER(субтитры, GigaAM) принятых клипов: медиана 0.00, p95 0.11. Высота лица p10: медиана 120 px, p5 93 px.

Калибровка порога пробы на известных образцах (30 с, 14 роликов: 5 хороших и 4-5 плохих, по которым нашлось лицо): корреляция
составного сигнала рта с речевой энергией. Хорошие: BBC-интервью 0.23, влог 0.28, интервью 0.15, второй влог -0.07, лекция МГУ 0.06;
плохие (озвучка/дубляж): гарвардская лекция с закадровым переводом 0.16, TED на русском 0.10, дублированный фильм 0.01, документалка о Гнесинке 0.05 (спорный образец: по кадрам говорящий настоящий, потом клипы с него прошли s7). Нулевая модель на 30 с даёт 95-й процентиль около 0.2: AUC хороших против плохих всего около 0.65,
то есть проба 30 с по этому признаку почти не различает. Поэтому порог пробы выставлен мягко (`probe_sync_min = 0.10`: отсекает только
явное отсутствие связи), а решение принимают s7/s8 на всём ролике с нулевой моделью.

## Что надо знать про качество фильтра синхронности (калибровка)

Подробные числа и распределения - в разделе «Результаты тестовой партии» выше. Коротко: проверка «активный говорящий»
по корреляции раскрытия рта с энергией речи на лицах высотой ~100 px при 360p **слабая**: на пробе 30 с значения хорошего
и плохого образцов перекрываются. Поэтому основная нагрузка в s7/s8: нулевая модель на каждом ролике (звук из другого места
того же ролика) даёт порог с ложным принятием около 5% на сегмент, а решение о ролике принимается по доле сегментов выше порога.
Это отбрасывает озвучку/закадровый голос, где слоги не совпадают, но не гарантирует отсутствие дубляжа с совпадающими паузами.
Заметное улучшение даёт SyncNet (код в `multivsr/preprocess/`, веса `syncnet_v2.model` ~54 МБ с robots.ox.ac.uk): его
использует серверный сборщик RuTube/VK (`rv_collect.py` + `gpu_server.py`, веса в `newdata/weights/`), а `collect.py` — нет.

## Известные ограничения

* Классическая корреляция губ и энергии на лицах ~100 px при 360p шумная: около половины настоящих говорящих роликов (в тесте 2 из 4)
  отбрасываются (ложные отказы), а дубляж с совпадающими паузами может проскочить. Для обучения это безопасная сторона (меньше
  данных, но меньше рассогласованных меток), но выход ниже теоретического. Улучшение: SyncNet (см. выше) или проверка ru-ASR vs
  VSR-модели на сегменте.
* Выход: на тесте 0.0074 часа клипов на ролик, дошедший до s2 (всего 2 принятых ролика, оценка очень грубая). Для 100 часов нужны
  сотни принятых роликов; ускоряет канал-буст: после принятого ролика его канал обходится (до 40 роликов, лимит 3 принятых на канал).
* Параллелизм по сети ограничен двумя обращениями к YouTube, поэтому сито s2 (yt-dlp -j, 4-15 с) и проба (ffmpeg по прямым ссылкам,
  ~20-25 с на 30 с видео, YouTube отдаёт поток со скоростью ~1.5x реального времени) дают около 2-3 роликов в минуту.
* Метки GigaAM нормализованы (нижний регистр, без пунктуации; ё сохраняется), цифры остаются как произнесены моделью.
