# Архитектура

Клавиатурное расширение iOS не может писать с микрофона, поэтому «Великий & Могучий» состоит из
приложения-ретранслятора и двух клавиатур. Приложение держит аудиосессию в фоне
(`UIBackgroundModes=audio`), сеть и запись делает только оно. Клавиатуры шлют команды
и забирают готовый текст.

```text
Великий & Могучий RU / Великий & Могучий EN (клавиатура)
  │  start / stop / cancel + requestID + язык (ru|en)
  ▼
Канал связи (RelayTransport)
  ├─ App Group: UserDefaults + flock-замки      (если контейнер доступен)
  └─ резервный: два именованных UIPasteboard + уведомления Darwin
  │
  ▼
Приложение: AudioCaptureEngine ─ PCM16 16 кГц, куски по 100 мс ─▶ DashScopeRealtimeSession
  │                     wss://dashscope-intl.aliyuncs.com или dashscope.aliyuncs.com (регион ключа)
  ▼
Результат (тот же канал) ─▶ UITextDocumentProxy.insertText (только если документ и контекст совпали)
```

## Цели сборки

| Цель | Что это |
| --- | --- |
| `VelikiyMoguchiy` | приложение (SwiftUI): ключ DashScope, настройка, история, голосовые заметки, ретранслятор |
| `VelikiyMoguchiyKeyboardRU` | клавиатура `ru-RU`, раскладка ЙЦУКЕН, диктует с `language=ru` |
| `VelikiyMoguchiyKeyboardEN` | клавиатура `en-US`, QWERTY, диктует с `language=en` |
| `VelikiyMoguchiyWidgets` | расширение WidgetKit: Live Activity «тёплого» микрофона (остаток, «Стоп», «Продлить»); необязательное |
| `VelikiyMoguchiyTests`, `VelikiyMoguchiyKeyboardPortTests` | модульные тесты |

Обе клавиатуры собираются из одних исходников (`KeyboardExtension`), отличаются только
`Info.plist` (`PrimaryLanguage`, `IsASCIICapable`, ключ `VelikiyMoguchiyKeyboardLanguage`).

## Протокол DashScope (проверен живым сервисом)

1. `session.created` → `session.update` (`modalities:["text"]`, `voice:"Serena"` обязательно,
   `input_audio_format:"pcm"`, `sample_rate:16000`, `turn_detection:null`,
   `input_audio_transcription.language`, `instructions`) → `session.updated`.
2. `input_audio_buffer.append` с base64 PCM16 моно 16 кГц, куски по ~100 мс.
3. Живое превью: `conversation.item.input_audio_transcription.delta` (`text`+`stash`).
4. Стоп: `input_audio_buffer.commit` + `response.create`; чистый текст приходит как
   `response.text.delta` / `response.text.done`, затем `response.done`. `session.finish` не отправляется.
   Тишина не коммитится (модель сочиняет текст на пустом звуке).
5. Если живой поток упал, сохранённая запись (WAV) проигрывается через тот же протокол.

Код: `App/DashScope/*`, тесты на фейковом сокете: `Tests/DashScopeRealtimeSessionTests.swift`.
Живая проверка протокола: `Scripts/dashscope_smoke.py`.

## Инварианты ретранслятора (унаследованы от основы)

1. У каждой операции UUID и время создания.
2. Разрешение на холодный запуск короткоживущее и забирается один раз.
3. Номер команды пишется после данных (маркер коммита); приложение подтверждает номер после обработки.
4. Отмена приоритетнее ещё не обработанного старта/стопа той же записи.
5. Клавиатура вставляет результат, только если совпали requestID и якорь документа.
6. Подтверждение результата стирает его текст, но не даёт старому подтверждению стереть новый результат.
7. Асинхронные задачи несут поколение/requestID, поэтому устаревшие не публикуются.

## Канал без App Group

`RelayTransport` при первом обращении проверяет, можно ли писать в контейнер App Group.
Если нет, `SharedRelayStore` работает поверх `PasteboardKeyValueStorage`:

- два именованных буфера обмена, у каждого один писатель (клавиатура пишет команды и запрос запуска,
  приложение пишет статус, превью и результат), поэтому процессы не затирают друг друга;
- «стирание чужих» ключей заменено подтверждениями (`relay.result.acked`, `relay.launch-claimed-id`);
- уведомления Darwin будят другую сторону сразу, без ожидания опроса;
- если клавиатура не подтвердила результат за 4 с, приложение кладёт текст в общий буфер обмена одним
  локальным элементом с истечением через 30 с; клавиатура забирает и тут же стирает его.

Ключ DashScope хранится только в Keychain приложения; клавиатуре передаётся лишь флаг «ключ есть».

## Отклик клавиш (вибрация и звук)

Настройки «Вибрация при нажатии» и «Звук клавиш (как в системе)» (обе по умолчанию включены) пишет приложение
(`AppConfiguration` → `SharedRelayStore.keyHapticsEnabled/keyClickSoundEnabled`, тот же канал, что и флаг ключа), клавиатура
читает их в `viewWillAppear` (`refreshKeyFeedbackPolicy`). Вибрация: `UIImpactFeedbackGenerator(.light)` на нажатие любой клавиши
(и на каждый повтор удаления), `UISelectionFeedbackGenerator` на смену выбора в панели акцентов и при сдвиге курсора пробелом;
только при `hasFullAccess` (`KeyFeedbackPolicy.shouldVibrate`), без него клавиатура молчит. Звук: `UIDevice.playInputClick()`
на нажатие; работает, потому что `view` контроллера (`KeyboardInputView`) принимает `UIInputViewAudioFeedback`, и подчиняется
системной настройке «Звуки клавиатуры».

## Сессия, прерывания, питание

- `RelaySessionPolicy` (чистые функции): длина сессии (настройка) и триггер (запуск, клавиатура, конец диктовки,
  «Продлить») дают дедлайн; `RelayPowerPolicy`: заряд < 10 % или режим энергосбережения. `RelayController`
  держит дедлайн отложенным вызовом и сверяет с часами в цикле опроса.
- `AudioRecoveryMachine` (чистая): события звука (прерывание, смена маршрута, сброс медиасервисов, остановка
  движка, возврат на передний план) дают действия; сессия не деактивируется нигде, кроме настоящей остановки.
  `AudioCaptureEvent.needsApp` превращается в `offlineReason = needsApp`.
- Live Activity: `LiveActivity/` (атрибуты и интенты, общие для приложения и расширения),
  `RelayLiveActivityController` (запрос только на переднем плане, остальное без падений).
- Опрос: Darwin-уведомления после каждой записи (App Group и резервный канал); таймеры 1 с и 200 мс (приложение),
  1 с и 250 мс (клавиатура).

## Клавиатура: касания и ввод

- `KeyTouchTracker` (чистый): одна обработка касаний на всю сетку. Ближайшая клавиша к точке, фиксация по
  отпусканию над клавишей под пальцем, новый палец фиксирует предыдущую клавишу, ⌫ действует при нажатии и
  ускоряется до слов, пробел: трекпад только по долгому нажатию (сдвиг пальца по пробелу при быстром наборе
  всё равно печатает пробел, как у Apple), долгое нажатие на букву открывает панель акцентов. Глобус остаётся настоящим `UIControl` (системное переключение клавиатур).
- `AutocapitalizationRules`, `SmartPunctuation`, `KeyboardInputProfile` (тип поля в раскладку),
  `SuggestionEngine` + `SuggestionComposer` + `AutocorrectRules`: чистая логика с тестами в `KeyboardPortTests`.
- Отслеживаемый запрос диктовки и «обработанный» номер результата лежат в общем хранилище
  (`relay.keyboard.*`), поэтому глобус RU↔EN не теряет результат.
