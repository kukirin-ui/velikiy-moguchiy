# «Великий & Могучий», federated: федеративное дообучение LoRA для чтения по губам

Каркас федеративного обучения: протокол, сервер приёма и агрегации, клиент (планировщик, обёртка тренера, упаковка,
отправка, загрузка модели), симуляция. Установка, владелец которой дал **отдельное согласие** (по умолчанию его нет:
`python -m client.runner consent on`), обучает LoRA-адаптер на своих данных и отправляет только дельту весов; без
согласия клиент ничего не делает. Текст согласия: `docs/AGREEMENT.md`.
Архитектура и обоснования: `docs/DESIGN.md`.

Сервер из `server/` работает **только на localhost** (эталон и симуляция). Для участников из интернета есть
отдельная связка «Помочь обучить» (ниже): сервер приёма на Cloudflare Workers, хранение на Hugging Face и агрегатор на
GitHub Actions. Сервер приёма развёрнут на Cloudflare Workers, агрегатор работает раз в сутки; шаги владельца — в
`docs/AUTOMATION.md`.

## «Помочь обучить»: обучение силами участников

Участник по кнопке в приложении получает задание (несколько публичных роликов YouTube и отрезки с расшифровкой),
сам качает и режет их со своего адреса, обучает LoRA у себя и отправляет **только обновление весов** и числа о
вкладе. Видео, звук и кадры лица с компьютера не уходят; личные папки приложения задание не трогает.

| Часть | Код | Что делает |
|---|---|---|
| Сервер приёма | `worker/` (Cloudflare Worker); тот же API на Python для Docker-Space — `space/`; общее с агрегатором — `hub/` | вход через GitHub (возраст аккаунта, лимиты на логин), задания из закрытого пула с учётом исключений `data-governance/`, приём только safetensors с подписью протокола v2 и подписанными сведениями о вкладе, хранение в закрытом датасете |
| Агрегатор (GitHub Actions, раз в сутки) | `aggregator/`, `.github/workflows/federated-aggregate.yml` | оценка без секретов: повторная проверка формата и подписей, скрытый экзамен каждого обновления (хуже — отклонено), не меньше 5 принятых, клиппинг и усечённое среднее с весом не больше задания, экзамен после слияния (хуже — не публикуется); публикация на отдельном раннере с ключом подписи: пересборка слияния, подписанная версия в репозитории модели на HF, откат, `contributors.json` |
| Клиент | `client/community.py`, `client/lipread_pipeline.py`, `client/privacy.py`, `client/github_login.py` | отдельное согласие, вход с устройства, yt-dlp (только видео), нарезка, кадры лица и признаки, обучение под охранником памяти с паузой и отменой, показ всего, что уйдёт, и отправка по кнопке |
| Деплой | `.github/workflows/federated-worker.yml` (wrangler из `worker/package-lock.json`) | поддомен `velikiy-moguchiy.workers.dev`, хранилище лимитов, секреты Worker, его адрес — в `client/community_defaults.py` |

Что владелец делает один раз (аккаунт Cloudflare, токены, секреты): [`docs/AUTOMATION.md`](../docs/AUTOMATION.md); как устроено: [`docs/DEPLOY.md`](docs/DEPLOY.md).

```bash
.venv/bin/python -m client.community status              # согласие, вход, состояние задания (JSON)
.venv/bin/python -m client.community consent on          # отдельное согласие на «Помочь обучить»
.venv/bin/python -m client.community login               # код для github.com/login/device
.venv/bin/python -m client.community run                 # задание целиком; обновление ждёт «send»
.venv/bin/python -m client.community preview             # что именно уйдёт на сервер
.venv/bin/python -m client.community send                # отправить (или discard — выбросить)
```

В приложении клиент ставится вместе с режимом «губы» (одна кнопка «Установить»; пакеты, включая `yt-dlp`, закреплены в
`lipread/uv.lock`). Из командной строки для `run` нужны папка lipread с окружением (`--lipread-dir` или
`training.lipread_ru_dir`), `yt-dlp` и `ffmpeg`: модельные шаги
идут через `lipread/train_on_me_worker.py` и `lipread/train.py` под `tools/mem_guard.py`; на Mac их пропускает только
`VELIKIY_MOGUCHIY_APP_JOB=help-train`, который ставит кнопка в приложении (клиент его сам не ставит, R11a в
`lipread/RULES.md`).

## Окружение

```bash
cd velikiy-moguchiy/federated      # из корня клона репозитория
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python numpy safetensors cryptography pydantic fastapi uvicorn python-multipart httpx huggingface_hub pytest torch
```

`torch` нужен только симуляции (`sim/run_sim.py`); сервер, протокол и клиент работают на numpy. Любой процесс с
PyTorch запускается под охранником памяти (бюджет = доступная память минус 6 ГБ, пауза при росте свопа):

```bash
python3 ../tools/mem_guard.py -- <команда>
```

## Тесты

```bash
python3 ../tools/mem_guard.py -- .venv/bin/python -m pytest
```

Покрыто: «Помочь обучить» (`tests/test_community.py`): только safetensors (pickle, torch.save и прочее отвергаются),
подпись сведений о вкладе, вход через GitHub и device flow, лимиты на логин (в том числе после перезапуска сервера),
задания и исключения (при недоступном списке исключений задания не выдаются), реестр версий и откат, раунд с
отклонением ухудшающего обновления, усечённое среднее, ожидание участников и устаревшие базы, слияние хуже базы,
откат при расхождении опубликованного файла, таблица вклада, личные папки, клиент не отправляет ничего, кроме трёх
частей (видео с маркером в запросах не встречается), полный цикл участники → сервер → агрегатор → новая версия у
клиента. Ранее: схема и строгость манифеста, подпись и подмена, спецификация/формы, NaN, лимиты размера; математика
клиппинга, усечённого среднего (взвешенного, по координатам), медианы, DP; приём на сервере (дубликат, конфликт,
устаревшая база, отравление, лимит на установку, блокировка), публикация версии и удаление дельт, откат, DP-бюджет,
хранение (`prune`), отказ слушать не-loopback; клиент: разбор `pmset`/`ioreg`, условия планировщика, учёт активного
времени при паузах охранника, повторы с задержкой, закрепление ключа TLS на настоящем HTTPS, проверка модели при
загрузке (чужой ключ, понижение версии, повреждение), полный цикл клиента, outbox; конвертер формата адаптера
через окружение lipread.

## Запуск сервера (localhost)

```bash
# 1. один раз: каталог данных, ключ подписи моделей, версия v1 (случайный A, B = 0)
.venv/bin/python -m server.admin init --data-dir server_data --spec protocol/specs/multivsr_lora_r16.json
#    при готовом начальном адаптере: --from-adapter initial.safetensors (ключи "<модуль>.A/.B", fp32)
.venv/bin/python -m server.admin keys --data-dir server_data        # публичный ключ подписи для клиента

# 2. настройки (необязательно): server_data/server.toml, см. server/config.py
#    [aggregation] method, trim_ratio, min_clients, clip_norm/clip_median_mult, max_weight_examples
#    [limits] max_update_norm, max_updates_per_client_per_day   [dp] enabled, noise_multiplier, delta, max_epsilon

# 3. сервер (только 127.0.0.1; на другой адрес не стартует)
.venv/bin/python -m server.run --data-dir server_data --port 8765 [--tls-cert cert.pem --tls-key key.pem]

# 4. раунд агрегации (вручную или по расписанию)
.venv/bin/python -m server.aggregate --data-dir server_data [--dry-run] [--force]

# 5. администрирование
.venv/bin/python -m server.admin status   --data-dir server_data
.venv/bin/python -m server.admin rounds   --data-dir server_data    # нормы, множители клиппинга, кто отброшен
.venv/bin/python -m server.admin versions --data-dir server_data
.venv/bin/python -m server.admin rollback --data-dir server_data --to 3 --reason "причина"
.venv/bin/python -m server.admin ban CLIENT_ID --data-dir server_data
.venv/bin/python -m server.admin prune --data-dir server_data --older-than-days 180
```

Самоподписанный сертификат для локального HTTPS и значение для закрепления: `sim/tls.py` (`make_selfsigned`).

## Запуск клиента

```bash
.venv/bin/python -m client.runner init        # ~/.velikiy-moguchiy-federated/{config.toml,identity.key}; печатает client_id
# отредактировать ~/.velikiy-moguchiy-federated/config.toml: server.url, signing_public_key, tls_spki_sha256, tls_ca_file,
# schedule.*, training.*, guard.*  (для http://localhost: allow_insecure_localhost = true)
.venv/bin/python -m client.runner consent on   # отдельное согласие на участие (без него проходы ничего не делают)
.venv/bin/python -m client.runner status      # условия сейчас: питание, простой, энергосбережение, последний манифест
.venv/bin/python -m client.runner once --dry-run --force     # обучить и упаковать, не отправляя
.venv/bin/python -m client.runner once        # один проход по расписанию
.venv/bin/python -m client.runner daemon [--parent-pid PID]  # демон; выходит вместе с родителем, как mic-warm
```

Бэкенд обучения: `training.backend = "stub"` (случайное блуждание, проверка труб, ничему не учит) или
`"lipread-ru"` (подпроцесс `lipread/train.py` под охранником памяти; **ещё не прогнан на реальных весах**,
см. ниже). Интерфейс: `client.trainer.train_lora(features_dir, base_adapter, steps, out, *, trainer=, should_stop=) -> TrainResult`.

## Симуляция

```bash

```

### Результаты (запуск на Mac, seed 0, воспроизводится)

Модель-заменитель: трансформер из 2 блоков, LoRA r=8 на q,v (2048 параметров), 8 классов синтетических последовательностей;
база предобучена без сдвига, у каждого клиента свой сдвиг признаков («домен») и свой перекос по классам (не IID),
размеры шардов 157–351. 10 локальных шагов на раунд. «Глобальная acc» — точность глобального адаптера на
сбалансированном тесте всех честных клиентов; в скобках среднее / минимум / максимум по клиентам на их собственных тестах.

| Раунд | Глобальная acc | Клиенты (среднее / мин / макс) | Злоумышленник → результат |
|---|---:|---|---|
| 0 (база) | 58,7% | 49,2 / 12,0 / 71,0 | — |
| 1 | 74,1% | 65,7 / 35,0 / 90,5 | дельта x1000 (норма 1085) → **отвергнута при приёме** (`norm_too_large`) |
| 2 | 86,8% | 86,0 / 52,5 / 96,0 | x6 (норма 6,48) → принята, **заклиплена x0,236**, отброшена в 77% координат |
| 3 | 92,4% | 92,5 / 70,0 / 98,0 | обратный знак x5 (норма 3,59) → x0,269, отброшена в 65% координат |
| 4 | 92,9% | 93,5 / 74,5 / 98,0 | обучение на сдвинутых метках x5 (норма 5,16) → x0,186, отброшена в 67% |
| 5 | 92,5% | 94,1 / 78,0 / 98,0 | x1000 (норма 639) → отвергнута при приёме |

У честных клиентов в раундах 2–3 доля отброшенных координат 3–44% (ожидание при `trim_k=1, n=11`: 18%), у отравителя 65–77%.
**Без защиты** (простое среднее, лимита нормы нет) та же атака x1000 в раунде 1 роняет глобальную точность до
**11,2%** (около случайного 12,5%), дальше она остаётся 10–13%.

Честные оговорки: (1) для сравнения клиент, обучающийся **только на своих данных** 50 шагов, получает на своём тесте
98,0% (среднее) — выше глобальной модели (94,1%). В этой игрушке сдвиг домена простой, а данных у клиента достаточно,
поэтому федерация тут не выигрывает у локального обучения на своём распределении; её смысл в обобщении на других
пользователей и на клиентов с малым числом примеров, чего эта симуляция не проверяет. (2) Нормы честных обновлений
в игрушке порядка 1, пороги (`max_update_norm = 8`, адаптивная C) подобраны под неё; для реального обучения их надо
калибровать по нормам первых раундов. (3) Атаки грубые; «тихое» отравление в пределах нормы здесь не моделируется
(раздел 6 DESIGN.md).

### Реальные формы MultiVSR (случайные веса, без обучения)

| Величина | Значение |
|---|---:|
| Тензоров / параметров | 144 / 1 769 472 |
| **Дельта fp16 (safetensors)** | **3 554 248 Б = 3,554 МБ (3,390 МиБ)** |
| Манифест с подписью | 528 Б |
| Глобальный адаптер fp32 (скачивание) | 7,093 МБ (6,765 МиБ) |
| Упаковка + подпись | ~8 мс |
| Отправка по HTTPS localhost с проверкой на сервере | ~30 мс |
| Расхождение с независимым расчётом агрегата | 1,9e-9 |

Если заморозить A (режим FFA-LoRA), дельта уменьшится вдвое (~1,8 МБ).

## Что осталось подключить, когда рецепт обучения по губам будет готов

1. **Реальный тренер.** `client/trainer.py: LipreadRuTrainer` собран по формату `lipread/train.py`
   (`--init-lora`, `--max-steps`, `--manifest`, `--mix`, `best.pt`/`last.pt` с ключом `lora`), конвертер формата
   проверен (`tests/test_convert.py`, ключи совпадают с `lora.py`). Через клиент на реальных весах MultiVSR
   ещё не прогонялся. Нужно проверить флаги, источники данных на клиенте
   (на клиенте есть только свои `silent`/`voiced`, без `public`-реплея), как считается `num_examples`, и режим
   «дообучение с локальным dev»; затем подставить число шагов, lr и `--time-mask/--noise` под федеративный режим.
2. **Начальный адаптер v1.** Сейчас случайный A, B=0. Лучше начать с адаптера, обученного централизованно на публичных
   данных (`server.admin init --from-adapter`), иначе первые раунды слабы.
3. **Калибровка порогов** по реальным нормам дельт: `limits.max_update_norm`, `clip_median_mult`/`clip_norm`, `trim_ratio`,
   `min_clients`, `steps`, `server_lr`. Решить, замораживать ли A (FFA-LoRA).
4. **Применение глобального адаптера в приложении «Великий & Могучий»:** загрузка `adapters/current` и слияние `W += (α/r)·B·A` при инициализации
   распознавателя; локальный `validator` на dev-наборе пользователя.
5. **Упаковка в приложение:** Python-сервис в бандле, запуск через `NSTask` с `--parent-pid` (как `mic-warm`), ключ подписи и
   закрепление TLS, Keychain вместо файла ключа.
6. **Перед выходом наружу:** развёртывание (см. начало этого файла), аттестация устройств (Sybil), безопасная агрегация, гейт качества
   перед публикацией версии, резервные копии и расписание `aggregate`/`prune`, сверка `docs/AGREEMENT.md` с фактическим развёртыванием.
