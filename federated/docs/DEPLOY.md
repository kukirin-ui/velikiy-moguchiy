# «Помочь обучить»: развёртывание

Шаги владельца, которые делаются один раз (аккаунт Cloudflare, токены, секреты), — в
[`docs/AUTOMATION.md`](../../docs/AUTOMATION.md), раздел «Помочь обучить». Здесь — как устроено и что где лежит.

```
 Mac участника                 Cloudflare Worker (federated/worker)        Hugging Face (z1gansh1n)
 client/community.py ──GET /v1/task──►  токен GitHub, лимиты (KV),  ──читает──► velikiy-moguchiy-inbox (закрыт)
   yt-dlp, нарезка, обучение            задание из пула                          pool/shards/*.jsonl
   ──POST /v1/updates──────────────►    проверка формата и подписей ──коммит──►  pending/<логин>/...
   ◄── версии адаптера, проверка подписи ──────────────────────────────────────── velikiy-moguchiy-lips (открыт)
                                                                                    index.json, versions/
 GitHub Actions (раз в день, federated/aggregator): pending/ ─► скрытый экзамен (velikiy-moguchiy-exam, закрыт)
   ─► усечённое среднее ─► экзамен после слияния ─► новая подписанная версия ─► contributors.json
```

## Сервер приёма (Cloudflare Worker)

`federated/worker/src/index.js`, деплой — `.github/workflows/federated-worker.yml` (wrangler). API то же, что у
`space/app.py`:

| Запрос | Что делает |
|---|---|
| `GET /v1/config` | Client ID приложения GitHub для входа, спецификация адаптера, лимиты |
| `GET /v1/task` + `Authorization: Bearer <токен GitHub>` | проверка логина (аккаунт не моложе 30 дней, не в бане), лимит заданий в сутки, ролики из случайного куска пула без каналов из `data-governance/exclusions/channels.tsv` (журнал недоступен — заданий нет), токен задания с HMAC |
| `POST /v1/updates` + тот же заголовок, multipart `manifest`, `payload`, `contribution` | ровно три части; размер; подпись манифеста (протокол v2) и сведений о вкладе; SHA-256 нагрузки; safetensors fp16 с тензорами из спецификации (pickle, zip, numpy отвергаются по сигнатуре); актуальная версия; токен задания этого логина; одно обновление на логин и версию; лимит в сутки; коммит в `pending/` датасета входящих |

Значения тензоров (конечность, L2-норма) Worker не разбирает: на бесплатном плане у запроса 10 мс процессора, а
агрегатор всё равно проверяет каждое обновление заново. Если Cloudflare начнёт отвечать «exceeded resources»,
выход — платный план Workers ($5 в месяц) без изменений кода.

Секреты Worker (ставит деплой): `HF_TOKEN` — это `HF_INTAKE_TOKEN` репозитория, fine-grained токен только на запись во
входящие; `FL_TASK_SECRET`. Ключа подписи модели у деплоя нет: открытая часть лежит в `client/community_defaults.py`.
Поддомен `workers.dev` аккаунта должен быть ровно `velikiy-moguchiy`, иначе деплой останавливается. wrangler
закреплён в `worker/package-lock.json` (`npm ci`).
Лимиты в KV: метки времени заданий и обновлений за сутки, выданные ролики, одно обновление на версию.

Спецификация адаптера, настройки обучения в задании и закреплённые файлы попадают в Worker из кода на Python:
`python worker/gen_defaults.py` пишет `worker/src/defaults.json` (тест следит, чтобы файл был свежим), а
`tests/test_worker_compat.py` проверяет, что подписи и токены, сделанные на Python, принимает Worker, и наоборот.

Запасной вариант: тот же API на Python (`space/app.py`, Docker, `space/deploy.py`) для Space на Hugging Face —
но Docker-Space на бесплатном CPU требует подписки PRO.

## Пул роликов и скрытый экзамен

Делается на поде или сервере, где лежат данные сборщика, не на Mac. Один раз на этой машине:
`pip install huggingface_hub && hf auth login`.

**Пул** — отрезки публичных роликов с расшифровкой из отбора сборщика. Клипы val/test, ролики экзамена и каналы из
журнала исключений в пул не идут. Worker читает пул кусками по 20 роликов:

```bash
cd federated && python -m space.build_pool --rows ../lipread/data/public_meta/ru.jsonl --channels channels.tsv --exclude-videos exam_videos.txt --out pool.jsonl --shards shards
```

```bash
hf upload z1gansh1n/velikiy-moguchiy-inbox shards pool/shards --repo-type dataset
```

**Экзамен** — публичные клипы, которых нет в пуле (MuAViC-ru, valid и test), с эталонными текстами. Записи автора
проекта в экзамен не входят никогда. Проще всего положить в датасет сами клипы — признаки посчитает задание оценки в
GitHub Actions (детектор лица из кода MultiVSR и визуальная часть lips-0.1 по закреплённым SHA-256, CPU, без секретов,
`aggregator/exam_features.py`, по умолчанию 120 клипов поровну по говорящим):

```
raw/exam_raw.jsonl  {"id": ..., "file": "<имя клипа>", "text": "<эталон>", "speaker": "<говорящий>", "raw": false} на строку
                    ("raw": false — клип уже вырезан по лицу, как в MuAViC-ru; true — исходное видео)
raw/<клип>.mp4
```

Либо готовые признаки (тогда задание их не считает):

```
exam.jsonl          {"id": "<16 hex>", "text": "<эталон>", "feats": "feats/<id>.npy"} на строку
feats/<id>.npy      признаки (T, 512), float16, 25 кадров в секунду
```

```bash
cd federated && python -m aggregator.build_exam --manifest MANIFEST.jsonl --split test --limit 80 --out exam
```

```bash
hf upload z1gansh1n/velikiy-moguchiy-exam exam . --repo-type dataset
```

Ни пул, ни экзамен в git не попадают.

## Агрегатор (GitHub Actions, раз в день)

`.github/workflows/federated-aggregate.yml`, код `aggregator/run.py`, два задания на разных раннерах, чтобы ключ
подписи не оказался рядом с кодом MultiVSR:

**Оценка** (секретов нет, кроме токена только на чтение в одном шаге скачивания). Копия входящих, текущей версии и
экзамена на диск; если `exam.jsonl` нет, раунд пропускается. CPU-torch и MultiVSR (код авторов с закреплённым
коммитом; `model.pth` с закреплённым SHA-256, загрузка только `weights_only=True`), сам экзамен — в подпроцессе с
пустым окружением. Решения пишутся в план (артефакт):

1. обновления на текущую версию; на старые базы, повторные и старше 30 дней — в удаление; меньше 5 свежих — ждём;
2. каждое заново: только safetensors, подписи, спецификация, конечность, норма; подпись описания базовой версии
   сверяется с ключом проекта;
3. скрытый экзамен базы и базы + каждого обновления; хуже базы — отклонено;
4. принятых меньше 5 — они ждут следующего раунда (одно обновление не публикуется никогда);
5. клиппинг и усечённое среднее принятых, вес обновления — число примеров, но не больше отрезков в его задании;
6. экзамен после слияния; хуже базы — версия не публикуется, текущей остаётся прежняя.

**Публикация** (без torch и MultiVSR; ключ подписи и токен записи только в этом шаге): сверяет базу и её подпись,
заново проверяет принятые обновления, сама собирает слияние и публикует его, только если SHA-256 совпал с планом;
сверяет опубликованный файл (при расхождении — откат); пишет `contributors.json` (часы и шаги не больше, чем было в
задании) и отчёт в `rounds/`; удаляет обработанные обновления и схлопывает историю датасета входящих
(`super_squash_history`), чтобы удалённые дельты не оставались в прошлых коммитах.

Откат вручную: тот же процесс с полем «Roll back to version N» (публикуется новая версия с содержимым N, версии
после N отзываются). Зеркало версий релизами в `velikiy-moguchiy-models` — с секретом `MODELS_REPO_TOKEN`.

## Mac участника

Ролик канала из журнала `data-governance/exclusions/channels.tsv` клиент пропускает сам: yt-dlp сообщает канал при
скачивании (у роликов пула из MultiVSR канал заранее не известен); журнал недоступен — задание не идёт.

Отдельно ничего ставить не нужно. Клиент обучения (`federated/client`, `federated/protocol`) входит в приложение и
ставится тем же нажатием «Установить», что и режим «губы» (`SPLipsRuntime`): код копируется в окружение приложения
(`lips/federated`), а его пакеты — `cryptography`, `pydantic`, `httpx`, `safetensors`, `yt-dlp` — закреплены вместе с
остальными в `lipread/uv.lock` (по хэшам), ffmpeg — тот же, что у режима «губы». Новая версия приложения с другим
кодом клиента пересобирает окружение. У разработчика вместо этого берутся `federated/` рядом с его папкой lipread и
её `.venv` (или `federated/.venv`, если есть). Модельные шаги идут с `VELIKIY_MOGUCHIY_APP_JOB=help-train` под
`tools/mem_guard.py` с лимитами «Обучить на мне» (R11a в `lipread/RULES.md`).

## Что где хранится

| Где | Что | Доступ |
|---|---|---|
| Cloudflare Worker | код сервера приёма, секреты `HF_TOKEN`, `FL_TASK_SECRET`, лимиты в KV | аккаунт Cloudflare |
| `velikiy-moguchiy-inbox` (закрытый) | `pending/` — обновления до проверки, `rounds/` — решения раундов (логины, числа), `pool/` — пул роликов | токены HF |
| `velikiy-moguchiy-lips` (открытый) | lips-0.1, `index.json` и все версии адаптера с подписанными описаниями | все |
| `velikiy-moguchiy-exam` (закрытый) | признаки и тексты экзамена | токены HF |
| GitHub | код, `contributors.json`, секреты процессов | все / владелец |
