# «Великий & Могучий» для Android: клавиатура RU/EN с голосовым вводом

Клавиатура (IME) с русской ЙЦУКЕН и английской QWERTY, подсказками и автоисправлением по тем же правилам, что
у клавиатуры для iPhone (`ios/`), и кнопкой диктовки. Диктовка идёт в Qwen через DashScope по вашему ключу,
как в приложениях для Mac и iPhone; без ключа — через распознавание речи Android (на телефоне, если оно есть).

**Статус: первая версия.** Код собирается и проходит модульные тесты в CI, но на живом телефоне ещё не
проверялся. Ждём отчётов в issues: модель телефона, версия Android, что не так.

- Android 6.0 и новее (minSdk 23), телефоны и планшеты.
- Клавиша 🌐 переключает русский и английский внутри клавиатуры; долгое нажатие на ней — список клавиатур Android.
- Нижний ряд: `[123] [🌐] [🎤] [пробел] [ввод]`, как у iPhone, только с клавишей языка.
- Долгое нажатие: `е → ё`, `ь → ъ`, буквы с диакритикой в английской раскладке, `« » „ “` на кавычке, `— –` на дефисе.
- Долгое нажатие на пробеле и движение пальцем двигают курсор; ⌫ с удержанием стирает буквы, потом слова.
- Долгое нажатие на 🎤 открывает настройки.

## Установка

1. Скачайте APK со страницы [Releases](https://github.com/zigansh1n/velikiy-moguchiy/releases):
   `VelikiyMoguchiy-Android.apk`, а пока ключ подписи в репозитории не настроен — `VelikiyMoguchiy-Android-debug.apk`.
   `-unsigned.apk` Android не ставит, он для тех, кто подписывает сборку сам. Свежая сборка из ветки лежит
   в Actions → «Build Android app» → артефакты.
2. Откройте APK на телефоне и разрешите установку из этого источника.
3. Откройте приложение «Великий & Могучий» и пройдите три шага: включить клавиатуру в списке клавиатур Android,
   выбрать её текущей, разрешить микрофон.
4. Для диктовки через Qwen: «Диктовка» → вставьте ключ DashScope → «Сохранить» → «Проверить». Ключ китайского
   региона работает только с адресом `dashscope.aliyuncs.com`, международный — с `dashscope-intl.aliyuncs.com`;
   регион выбирается там же.

Как диктовать: нажмите 🎤 — над клавишами появится строка «Слушаю…» с текстом по мере речи. «Готово» (или 🎤 ещё раз)
заканчивает диктовку, текст вставляется в поле целиком. ✕ отменяет. Пока идёт диктовка, остальные клавиши не
печатают, чтобы курсор не уехал. Если за это время вы ушли в другое поле, над клавишами появится «Вставить».

## Архитектура

Один модуль `app`, Kotlin и Jetpack Compose, Gradle с каталогом версий (`gradle/libs.versions.toml`).
Код разделён на чистую логику (тестируется на JVM без Android) и тонкий слой Android.

| Пакет | Что внутри | Откуда перенесено |
| --- | --- | --- |
| `keyboard/` | раскладки и состояние Shift/страниц (`KeyboardLayout.kt`), тип поля из `EditorInfo` (`InputProfile.kt`), автозаглавные, «умная» пунктуация, повтор ⌫ (`TextRules.kt`), подсказки и автоисправление (`SuggestionRules.kt`, `SuggestionEngine.kt`), словарь (`WordList.kt`), набор с откатом исправления по ⌫ (`TypingController.kt`), геометрия клавиш (`KeyboardGeometry.kt`), касания (`KeyTouchTracker.kt`) | `ios/Shared/Keyboard/*`, `ios/KeyboardExtension/Controller/KeyboardViewController+Suggestions.swift` |
| `dictation/` | протокол DashScope realtime (`DashScopeProtocol.kt`), сеанс на корутинах (`DashScopeSession.kt`), запись 16 кГц (`AudioRecorder.kt`), распознавание Android (`SystemSpeech.kt`), выбор провайдера и состояния (`DictationController.kt`) | `ios/App/DashScope/*`, `mac/velikiy-moguchiy-asr/src/qwen.rs` |
| `ime/` | `KeyboardService` (`InputMethodService`), экран клавиатуры на Compose (`KeyboardScreen.kt`, `KeyDrawing.kt`), загрузка словарей (`Dictionaries.kt`) | `ios/KeyboardExtension/*` |
| `settings/` | настройки и ключ (`AppSettings.kt`), экран настроек на русском (`SettingsActivity.kt`) | `ios/App/UI` |

### Клавиатура

- **Раскладки и правила — те же, что на iPhone.** Ряды ЙЦУКЕН/QWERTY, варианты по долгому нажатию, страницы
  «123» и «#+=», двойное нажатие Shift — Caps Lock, автозаглавные с исключениями для сокращений («т.е.», «ул.»,
  «Mr.», инициалы), «ёлочки» в русском и “лапки” в английском, `--` → `—`, `...` → `…`, точка двойным пробелом.
- **Геометрия** тоже перенесена с iPhone: поля 6,5 и зазор 6 точек при ширине 402 масштабируются под ширину
  экрана, у русской раскладки 11 равных клавиш в ряду, Shift и ⌫ у английской шире. Касание в зазоре попадает в
  ближайшую клавишу; клавиша печатается при отпускании, а если до этого опустился второй палец — в этот момент,
  чтобы при быстром наборе буквы не менялись местами.
- **Тип поля** берётся из `EditorInfo`: e-mail, адрес, поиск, цифры, телефон, пароль. В паролях и технических
  полях подсказок, исправлений и «умной» пунктуации нет; у цифровых полей своя панель с клавишей действия.
- **Клавиша ввода** выполняет действие поля (отправить, найти, далее, готово) и рисует его значок; в многострочных
  полях без действия ставит перевод строки.

### Подсказки и словарь

На iPhone подсказки дают системные `UITextChecker` и `UILexicon`. У Android нет такого API для клавиатур, поэтому
словарь едет внутри APK: частотные списки слов из AOSP LatinIME (Apache-2.0), около 183 тыс. русских словоформ и
92 тыс. английских (`app/src/main/assets/dictionary`, собираются `tools/build_wordlists.py`; скрипт выбрасывает
слова, которые privacy guard считает личными именами). Поиск не различает регистр и «ё/е»: «еще» считается словом,
а в подсказках будет «ещё».

Правила те же, что в `ios/Shared/Keyboard/SuggestionRules.swift`: три ячейки — набранное слово (в кавычках, если
его нет в словаре) и два кандидата; автоисправление только для незнакомого слова от трёх букв, на одну правку от
кандидата, не трогает «NASA», «iPhone» и слова, которые вы вернули через ⌫. Отличие: продолжения слова
(«здравс» → «здравствуйте») идут раньше исправлений на одну букву, потому что у списка слов нет «нечётких»
продолжений, как у `UITextChecker`. Из AOSP взяты и явные исправления опечаток («щас» → «сейчас», «im» → «I'm»).
Слова и сокращения из личного словаря Android работают как замены текста на iPhone.

Подсказки считаются в отдельном потоке, по одной задаче за раз и только для последнего текста, как на iPhone.

### Диктовка

- **С ключом DashScope** — тот же протокол, что в `ios/App/DashScope/DashScopeProtocol.swift` и
  `mac/velikiy-moguchiy-asr/src/qwen.rs`: WebSocket `wss://…/api-ws/v1/realtime?model=…`, ключ только в заголовке
  `Authorization`, `session.update` с отключённым определением пауз, PCM 16 кГц моно кусками по 100 мс в base64,
  по окончании `input_audio_buffer.commit`. Две модели на выбор:
  - `qwen3-asr-flash-realtime` (по умолчанию, как в приложении для Mac) — дословно и быстро, затем `session.finish`;
  - `qwen3.8-omni-flash-realtime` (как на iPhone) — `response.create`, модель переписывает речь в аккуратный текст
    с пунктуацией. Ответ Omni принимается, только если распознавание входа услышало речь: на тишину модель
    отвечает «Не расслышал…».
- Запись начинается сразу по нажатию, звук копится, пока открывается соединение. Тишину (тише −52 дБ, как на
  iPhone) клавиатура не отправляет на распознавание. Диктовка длится не дольше 5 минут.
- **Без ключа** — `SpeechRecognizer` Android: на Android 12+ сначала распознавание на устройстве, а если оно не знает
  языка — обычный сервис распознавания (часто сетевой). Если распознавания нет вовсе, клавиатура просит добавить ключ.
- На iPhone клавиатура не может записывать звук и передаёт работу приложению через общий контейнер. На Android
  клавиатура записывает сама, поэтому этой части (`ios/Shared/Relay`) здесь нет.

### Настройки и ключ

Экран настроек — обычная Activity на Compose, по-русски: шаги подключения, ключ DashScope с проверкой (открывает
сеанс и ждёт `session.updated`), регион, модель, переключатели набора, поле для пробы. Ключ шифруется AES-GCM
ключом из Android Keystore и хранится только на телефоне: резервное копирование приложения выключено.

### Почему minSdk 23

API распознавания (`SpeechRecognizer`), записи (`AudioRecord`) и клавиатур есть и в более старых Android, но
текущие AndroidX и Compose требуют Android 6.0 (API 23). Распознавание на устройстве
(`createOnDeviceSpeechRecognizer`) включается на Android 12+, на старых используется обычный сервис.

### Почему не Rust-ядро из `mac/`

Решение: **не подключать** `mac/velikiy-moguchiy-core` к Android, ни через JNI, ни через uniffi.

- Для клавиатуры из ядра нужен только протокол Qwen — около 300 строк. Остальное ядро — настольное: горячие
  клавиши, вставка через Accessibility, конфиг, менеджер моделей, LLM-постобработка, MLX и sherpa-onnx.
- Ядро тянет tokio, reqwest, rustls, audiopus. Сборка под четыре ABI Android добавила бы в CI NDK и кросс-компиляцию,
  а в APK — по несколько мегабайт на ABI, плюс слой JNI/uniffi с собственными ошибками и отладкой.
- iPhone поступил так же: у него свой клиент DashScope на Swift, протокол проверен вживую и покрыт тестами. Kotlin-
  версия повторяет его и Rust-версию по шагам, а различия поймают модульные тесты на поддельном сервере.
- «Словарь» ядра (`dictionary.rs`) — это список терминов для подсказки модели распознавания, а не словарь для
  набора, поэтому подсказкам клавиатуры он не помогает.

Пересмотреть стоит, если Android понадобятся многие провайдеры ядра (Doubao, GLM, локальные модели): тогда
выгоднее выделить из ядра лёгкий крейт только с провайдерами и подключить его через uniffi.

## Сборка и проверка

Нужны JDK 17+ и Android SDK с платформой 37.

```sh
cd android
./gradlew testDebugUnitTest     # модульные тесты
./gradlew assembleDebug         # app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease       # без ключа подписи: app-release-unsigned.apk
```

CI (`.github/workflows/build-android.yml`, Linux) на каждый push в main и PR с изменениями в `android/` гоняет
тесты и собирает оба APK; тег `v*` прикладывает их к черновику релиза через `release.yml`, тег `android-v*`
собирает только Android. Версия берётся из тега: `v0.2.1` → `versionName 0.2.1`, `versionCode 201`.

Подпись релиза: один раз выполните `android/scripts/make-signing-key.sh` у себя и добавьте четыре секрета, которые
он покажет (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`).
Файл ключа и пароль храните сами: APK, подписанный другим ключом, не сможет обновить установленный.

Словарь пересобирается так (скачивает закреплённую версию из AOSP и сверяет контрольные суммы):

```sh
python3 android/tools/build_wordlists.py --download
```
