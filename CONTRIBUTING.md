# Как помочь «Великому & Могучему»

Спасибо, что заглянули. Проект открыт: можно присылать код, сообщать об ошибках, предлагать идеи, а позже — помогать
данными и вычислениями для чтения по губам. Как мы общаемся — в [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

## С чего начать

- **Ошибка или идея** — откройте [issue](https://github.com/zigansh1n/velikiy-moguchiy/issues/new/choose) по шаблону.
  Для ошибки пригодятся версия macOS/iOS, модель Mac или iPhone, провайдер распознавания и шаги, чтобы повторить.
  **Не вставляйте ключи API, записи голоса, видео с лицом и личные тексты** ни в issue, ни в логи.
- **Код** — форк, ветка, pull request в `main` по шаблону. Один PR — одна задача; большие изменения лучше сначала
  обсудить в issue.
- **Уязвимость** — не в открытом issue: используйте приватный отчёт GitHub (Security → Report a vulnerability).

## Как запустить и проверить каждую часть

### Mac (`mac/`)

```bash
brew install cmake xcodegen          # плюс Xcode и rustup
cd mac
cargo test --workspace --no-default-features   # ядро и CLI, работает и на Linux
make build && make install-app                 # приложение целиком (нужен Mac на Apple Silicon)
```

Логика на Objective-C покрыта целью `VelikiyMoguchiyLogicTests` (Xcode → Product → Test). Перед PR, который трогает
приложение, соберите его и проверьте удержание и переключение клавиши диктовки.

### iPhone (`ios/`)

```bash
cd ios
xcodegen generate
Scripts/test.sh                      # модульные тесты в симуляторе
Scripts/build-unsigned-ipa.sh        # IPA без подписи, как в CI
```

Проект Xcode генерируется из `project.yml`: правьте его, а не `project.pbxproj` (закоммиченный pbxproj держим в
согласии с `xcodegen generate`). Изменения раскладок проверяет `Scripts/parity/parity.sh` (совпадение с клавиатурой
Apple), он же обязателен перед `Scripts/build-ipa.sh`.

### Чтение по губам (`lipread/`)

```bash
cd lipread
./setup.sh && ./download_weights.sh  # MultiVSR и веса — у авторов, около 5 ГБ
python3 -m pytest harvester/test_pilot_train.py harvester/test_course_loop.py   # офлайн-тесты
```

Шесть тестов в `test_course_loop.py` требуют служебного модуля RunPod, которого нет в репозитории; CI их пропускает.
Точный список команд и исключений — в задании `lipread` в [`.github/workflows/tests.yml`](.github/workflows/tests.yml).

Любой запуск модели — только под охранником памяти (`../tools/mem_guard.py`), правила в `lipread/RULES.md`.
Код MultiVSR в репозиторий не добавляйте: его лицензия не указана; правки к нему вносит `multivsr_compat.py`.

### Общее обучение (`federated/`)

```bash
cd federated
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python numpy safetensors cryptography pydantic fastapi uvicorn python-multipart httpx pytest
.venv/bin/python -m pytest
```

## CI

- `tests.yml` — на каждый PR: тесты ядра на Rust (Linux), `federated`, офлайн-тесты `lipread`; запускается только то,
  что затронуто.
- `build-apple.yml` — сборка приложения для Mac и IPA. Минуты macOS дорогие, поэтому сборка идёт только по метке
  `build` на PR (сопровождающие ставят её перед слиянием), по тегу или вручную.
- `release.yml` — раз в день выпускает новую версию, если с прошлого релиза изменилось приложение и все проверки
  `main` зелёные. Заметки к выпуску составляются из заголовков слитых PR, поэтому заголовок PR пишите по-русски и
  так, чтобы он был понятен пользователю. Номер версии растёт в третьей цифре; `[minor]` в заголовке PR или в
  сообщении коммита поднимает вторую, `[major]` — первую ([`docs/AUTOMATION.md`](docs/AUTOMATION.md#релизы)).
- `contributors.yml` — таблица участников в README из `contributors.json`.

## Стиль

- **Rust**: `cargo fmt` для изменённых файлов, `cargo clippy` без новых предупреждений, тесты рядом с кодом.
- **Objective-C / Swift**: как в окружающем коде (отступы, именование `SP…`, комментарии по-английски).
- **Python**: стандартная библиотека там, где можно; тесты на pytest или unittest; модельные задачи — под охранником памяти.
- **Тексты интерфейса** — по-русски, естественно и коротко; название — «Великий & Могучий».
- **Коммиты** — по-английски, в повелительном наклонении, одна логическая правка на коммит; в описании — что и зачем.
- **Документы и README** — по-русски.
- Не добавляйте ключи, личные пути, адреса почты, фото и видео людей, веса и данные со сторонними лицензиями
  (что можно и что нельзя — в [`THIRD_PARTY.md`](THIRD_PARTY.md)).
- **Проверка приватности** (`tools/privacy_guard.py`) идёт в CI на каждый push и PR: ключи, личные пути и
  идентификаторы, имена людей из собранных роликов, списки роликов и каналов, фото, видео и звук вне папок оформления
  (`design/`, `docs/assets/`, `*.xcassets`, `ios/Tests/Reference/`, `ios/screenshots/`), подписи соавторов-ИИ в
  коммитах. Запустить у себя: `python3 tools/privacy_guard.py`; перед коммитом — `python3 tools/privacy_guard.py --staged`
  (можно поставить в `.git/hooks/pre-commit`). Отчёт называет файл и строку, но не найденный текст.
  В документах (`.md`, шаблоны issue) она же не пропускает черновики: «черновик» в заголовке или плашке, заметки
  юристу и самим себе, `TODO`, `FIXME`, `TBD` и заглушки в квадратных скобках вроде `[куда писать]` (ссылки, флажки, код и
  пометки состояния вроде `[план]` не в счёт).
- **Проверка текстов** (`.github/workflows/text-review.yml`): в PR языковая модель читает добавленные строки
  документов и оставляет замечания в PR. Замечание с важностью high (личные данные, атрибуция ИИ, черновик, заглушка)
  не даёт слить PR; если модель недоступна, проверка только предупреждает. Ложное срабатывание добавляется в
  `tools/text_review/allowlist.txt` с объяснением.

## Данные и вычисления (позже)

Когда общее обучение заработает, помочь можно будет ещё двумя способами. Оба — только по отдельному явному согласию,
выключенному по умолчанию (см. [`PRIVACY.md`](PRIVACY.md)):

- **Часы своих данных для чтения по губам.** Клипы записываются и хранятся только на вашем Mac; наружу они не уходят.
- **Шаги обучения на своём железе.** Ваш Mac дообучает небольшой адаптер, на сервер уходят только изменения весов
  (`federated/`).

Вклад попадёт в таблицу участников в [README](README.md#сообщество): часы данных, шаги обучения и число принятых
обновлений весов. Таблицу ведёт автоматика по [`contributors.json`](contributors.json); правки вносятся туда, не в
README. Пока сервер общего обучения не развёрнут, ничего отправлять не нужно — следите за [дорожной картой](README.md#дорожная-карта).
